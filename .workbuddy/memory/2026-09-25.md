# 2026-09-25 工作日志

## 复查「智能调整网卡优先级」（RouteMetric）——发现并修复致命的假成功

用户反馈：进入房间后 ZeroTier 网卡 metric 依然不是 1，尽管日志写着成功，要求查日志找问题。

### 铁证（真机实测，Windows 本机）
用 `Get-NetIPInterface -InterfaceAlias 'ZeroTier One [bb40b36408000001]'` 实测 → **NO MATCH（返回 null）**。
原因：**PowerShell 的 `-InterfaceAlias` 支持通配符，别名里的方括号 `[bb40b36408000001]` 被当成「字符集」**，
匹配不到任何网卡。而 `Set-NetIPInterface` 对「匹配 0 个对象」**不报错、退出码 0** ——
于是旧代码 `Ps.IsSuccess`（只看退出码）判定成功、记日志、**永远不走 netsh 回退**，metric 实际从未被改动。

同时发现 netsh 回退路径**语法本身就是错的**：
`netsh interface ipv4 set interface name="..." metric=1` → `'name' is not a valid argument`。
正确语法是 `set interface <索引|名称> metric=<n>`（参数名不是 `name=`）。
更坑的是 **netsh 语法错误时也打印用法并返回退出码 0** —— 只看退出码同样是假成功。

第三个问题：**Debug 构建清单是 asInvoker、不自动提权**
（`app.manifest` 无 requestedExecutionLevel；只有 `app.require-admin.manifest` 在 `Configuration == Release` 时生效）。
非管理员下 `Set-NetIPInterface` 报 `Access is denied.`，旧代码的方括号静默无操作把「没权限」也伪装成了「成功」。

另有：Linux 用 `ip link set dev <iface> metric <n>` —— **该参数不存在**（`metric` 是 BSD ifconfig 的概念，iproute2 的 ip link 没有）。

### 修复（客户端 kiriyamalauncher）
- `Data/Services/RouteMetric/IRouteMetricService.cs`：`NetworkInterfaceInfo` 新增第 4 个字段 `int? IfIndex`（可选参数，旧调用不受影响）。
- `WindowsRouteMetricService.cs`（重写）：
  - 枚举时**保留 ifIndex**（`Get-NetAdapter ... Select Name,InterfaceDescription,ifIndex`）。
  - 下发**一律用 `-InterfaceIndex`（纯数字）而不是 `-InterfaceAlias`** —— 免疫方括号通配符。
  - **设置后读回校验**（`Get-NetIPInterface ... .InterfaceMetric == 目标值` 才算成功）—— 这是真正堵住假成功的关键。
  - 回退 netsh 用正确语法 `interface ipv4/ipv6 set interface <ifIndex> metric=<n>`。
  - 读不到 ifIndex 时**明确报失败**，不做按别名的冒险下发。
  - netsh 回退枚举改用 `netsh interface ipv4 show interfaces`（固定数字列，与系统语言无关），
    替代原先依赖中文「专用」/英文 Dedicated 的 `netsh interface show interface` 解析。
  - PowerShell 脚本内 catch 里捕获 `$_.Exception.Message` 一起回传 → 失败原因可见；
    识别 `Access is denied` / `requires elevation` → 输出「需要管理员权限（Debug 不自动提权，请用 Release 或让 IDE 以管理员启动）」。
- `LinuxRouteMetricService.cs`（重写）：改为 `nmcli`-free 的**路由 metric 方案** ——
  列出该接口的 IPv4 路由（`ip -o -4 route show dev <iface>`），逐条 `ip route replace <prefix> dev <iface> [src <addr>] metric <n>`，
  再读回校验；权限不足给 `sudo` 提示。`metric` 参数由路由承载，语义等价于「接口优先级」。
- `MacRouteMetricService.cs`：`ifconfig <iface> metric <n>` 保留（BSD 确实支持），增加读回校验；
  若本机 ifconfig 不回报 metric，如实标注「未能校验」而不谎报成功。
- `ZeroTierClientBackend.RaiseVirtualInterfacePriorityAsync`：失败时也 `EventRaised` 播报，不再静默。
- 三处正则全部改为 `[GeneratedRegex]` 源生成（项目 NativeAOT + 全裁剪发布，全库此前无正则使用）。

### 验证方式（无管理员权限下的最大化验证）
- 把 metric 设成 33 再读回 → 仍 35，且 `$Error.Count=0` → 证明非匹配别名是**静默无操作**。
- 新 SET 脚本（非管理员）→ `{"IPv4":-1,"IPv6":-1,"Error":"Access is denied.\r\n"}` → 错误原因被正确捕获。
- 新 READ 脚本 → `{"IPv4":35,"IPv6":100,"Error":""}` → 读回正确，且物理网卡 metric 前后不变（无副作用）。
- netsh 行正则实测解析正确（idx/met/name）。
- 四个 netsh 语法变体（索引/`interface=`/ipv6/名称）均通过语法解析，只在提权处失败 → 语法正确。
- 客户端 Debug 编译 0 错误。

### 经验教训
- **系统命令的退出码不可信**：netsh 语法错误返回 0；PowerShell 的 Set-NetIPInterface 匹配 0 个对象也返回 0。
  凡是「改了系统状态」的操作，**必须读回校验实际值**，不能只看退出码。
- **PowerShell 的 `[ ]` 是通配符**：任何把带方括号的名字传给 `-InterfaceAlias` / `-Name` / `-Path` 的地方都要转义或改用索引。
- **提权是隐式的**：Debug 与 Release 用不同 manifest，调试时管理员权限相关功能会静默失效。
