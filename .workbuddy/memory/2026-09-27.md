## 修复「连接虚拟局域网失败：'0x0D' is invalid within a JSON string」（客户端）

**现象**：朋友的机器上点「连接到虚拟局域网」直接弹错，报
`'0x0D' is invalid within a JSON string. The string should be correctly escaped. LineNumber: 20 | BytePositionInLine: 25.`；
房主自己的机器正常。

**根因链路**（已定位到具体调用点）：
`ZeroTierClientBackend.StartAsync` → `PruneLeftoverNetworksAsync`（连接前清理遗留网络成员资格）
→ `ExtractNetworkIds` → `ParseListNetworksJson` → `JsonDocument.Parse` **全程没有 try/catch**，
`JsonException` 一路冒到 `GameSessionViewModel.ConnectToVirtualNetworkAsync` 的 catch → 弹 toast。

这一步解析的是**本机 ZeroTier 服务当前已加入的全部网络清单**（`zerotier-one_x64.exe -q listnetworks -j`），
每台机器不同：清单里只要有任意一个网络的字段（如 `name`）带裸 CR/LF，整段 JSON 就非法，
`System.Text.Json` 直接拒收 → 连接流程在解析阶段就死了。房主机器清单正常所以不复现。

**改动**（`kiriyamalauncher.Data/Services/ZeroTierClientBackend.cs`）：
1. 新增 `SanitizeJsonStringLiterals`：解析前清掉**字符串字面量内部**的裸控制字符（CR/LF/TAB/NUL 等），
   字符串外的缩进换行原样保留，转义序列（`\"`、`\\`）按两字符跳过不误伤；输出合法时零分配（原样返回）。
2. `ParseListNetworksJson` / `listpeers -j` 解析前都过一遍该清理。
3. `ExtractNetworkIds` 由 static 改实例方法，内部 catch `JsonException` → 记 warn（含输出片段 `BuildSnippet`）后返回空表：
   清理遗留网络是尽力而为，解析失败不再打断连接，join 照常继续。
4. `RefreshSnapshotAsync`：解析失败按「本轮刷新失败」处理（计数 + warn + 保留上一份快照），不再抛出。
5. `RunProcessAsync` 增加可选 `outputEncoding`，ZeroTier CLI 调用统一按 **UTF-8** 解码（原来按控制台代码页
   即 GBK 解，中文网络名会乱码，且不同区域机器表现不一致）。

**验证**：.NET 10 单文件程序 + 与实现完全一致的算法副本实测：
- 构造「字符串里夹裸 CR」的 listnetworks JSON → 复现出**完全相同**的报错文案；清理后可正常解析出 nwid/status。
- 合法转义序列不被误伤；合法 JSON 原样返回（`ReferenceEquals == true`）；裸 TAB 同样被清掉。
- `dotnet build kiriyamalauncher.slnx` → 0 错误（8 个警告均为既有 CS0108/CA1416）。

**留下的排查线索**：新加的 warn 日志会打出畸形输出的片段，朋友机器上再出问题可直接看日志定位是哪个网络名作祟。
