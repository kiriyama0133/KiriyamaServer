## 架构方向调整：从「自建 UDP 中继」改为「ZeroTier Controller Tag + Flow Rules」（同日第二轮）

## 第三轮修正：Flow Rules 用 rulesSource DSL + 平台抽象（同日）

### 关键纠正（对照官方文档 rules engine / FAQ）
- **Flow Rules 的正确载体是 `rulesSource`（DSL 文本字符串）**，不是 `config.rules` 数组。第二轮把规则写成了结构化 JSON（`MATCH_TAGS_DIFFERENT`）是错的，已推翻。
- **Tag 定义写在 DSL 里**（`tag room_id id 1 default 0;`），不是网络配置的 `config.tags` 数组。
- **房间隔离的正确 DSL**（客户端隔离模式，来自官方 FAQ「Client Isolation」）：
  ```
  accept ethertype arp;
  tag room_id
    id 1
    default 0
  ;
  break not tor room_id 1;
  accept;
  ```
  语义：放行 ARP（节点互相发现）→ 声明 room_id 标签 → 双方 room_id 不都为 1 时 break（落到默认 drop）→ 其余（同房间）放行。`tor`=tag OR（任一方），`tdiff`=tag difference（双方差异）。
- **Tag id 定为 1**（与 DSL `id 1` 对齐），之前用 1000 是错的。成员打 tag 用 `tags: [[1, value]]`。

### 平台抽象（用户核心诉求：运行时不确定 Windows/Linux）
- 新增 `IZeroTierControllerPlatform` 抽象（驱动端口）+ `RuntimeZeroTierControllerPlatform` 实现（用 `OperatingSystem.IsWindows()` 运行时判定）。
- authtoken.secret 默认路径随平台：
  - Linux（Debian/Ubuntu）：`/var/lib/zerotier-one/authtoken.secret`
  - Windows：`C:\ProgramData\ZeroTier\One\authtoken.secret`
- `ResolveAuthTokenAsync(configuredToken)`：优先显式配置的 AuthToken，未配置则从平台默认路径读文件。
- `DefaultControlUrl` 统一 `http://localhost:9993`。
- `ZeroTierControllerOptions.ControlUrl` / `AuthToken` 改为可空：留空时由平台适配器兜底。
- `SelfHostedZeroTierController` 注入 `IZeroTierControllerPlatform`，HTTP 调用前先 `ResolveAuthTokenAsync` 拿 token。

`InvalidOperationException: A suitable constructor for type 'SelfHostedZeroTierController' could not be located. A Typed client must provide a constructor taking a 'System.Net.Http.HttpClient'...`

### 根因
`RoomsExtensions.AddRooms` 里误用 `services.AddHttpClient<SelfHostedZeroTierController>()`（Typed HttpClient）。Typed HttpClient 要求构造函数必须有一个 `HttpClient` 参数，但这两个 Controller 的构造函数注入的是 `IHttpClientFactory`（内部自己 `CreateClient(nameof(...))` 建客户端），不含 HttpClient 参数 → DI 找不到合适构造器。

### 修复（RoomsExtensions.cs）
- `AddHttpClient<SelfHostedZeroTierController>()` / `AddHttpClient<OfficialApiZeroTierController>()` 改为：
  - `AddHttpClient(nameof(SelfHostedZeroTierController))` / `AddHttpClient(nameof(OfficialApiZeroTierController))`（具名 HttpClient，因为实现内部 `CreateClient(名字)` 需要）。
  - `AddSingleton<SelfHostedZeroTierController>()` / `AddSingleton<OfficialApiZeroTierController>()`（普通单例注册服务类）。
- 工厂 `sp.GetRequiredService<...Controller>()` 保持不变。

### 教训
注入 `IHttpClientFactory` 手动建客户端的类，**不要**用 `AddHttpClient<T>`；要用 `AddSingleton/Scoped` + 具名 `AddHttpClient("name")`。

### 现象

## 修复：token 端点 400——[FromForm] 字段名不匹配（2026-09-15 深夜）

### 现象
注册（201）、登录（200）都成功，但紧接着 `/api/auth/token` 返回 400。日志关键行：
```
Attempting to bind property 'TokenRequest.GrantType' using the name 'GrantType' ...
Could not find a value in the request with name 'GrantType'
→ ModelStateInvalidFilter 短路 → BadRequestObjectResult(ValidationProblemDetails)
```

### 根因
OAuth token 端点的 form 字段名是标准 snake_case（`grant_type`/`code_verifier`/`client_id`），但服务端 `TokenRequest` 属性是 PascalCase（`GrantType`/`CodeVerifier`/`ClientId`）。`[FromForm]` 默认按**属性名**匹配，匹配不到 → `[Required]` 校验失败 → 400。客户端发的 snake_case 字段名（`FormUrlEncodedContent` 的 key 就是 snake_case）从未被读到。

### 修复
`TokenRequest.cs` 每个属性加 `[FromForm(Name = "grant_type")]` 等显式 snake_case 字段名（GrantType→grant_type、Code→code、CodeVerifier→code_verifier、RefreshToken→refresh_token、ClientId→client_id）。加 `using Microsoft.AspNetCore.Mvc;`。编译 0 错误。

### 教训
`[FromForm]` 不像 `[FromBody]` 走 JSON 反序列化（默认 camelCase），它按属性名做键值匹配；协议字段名与属性名不一致时必须显式 `[FromForm(Name = "...")]`。

## 修正：中继服务器模式 = 自建控制器网络（连接时自动接入 ZeroTier）（2026-09-15 深夜第四轮）

### 用户澄清（关键认知纠正）
「中继服务器模式不就是要使用到自建控制器吗」——即 Relay 模式本质上就是**服务端自建 ZeroTier Controller**（用 Flow Rules + Tag 做房间隔离），不是「只连 HTTP 房间大厅、不碰 ZeroTier」。之前把两者割裂是错的。

### 根因
客户端 `GameSessionViewModel.ConnectToRelayServerAsync` 之前只调 `Rooms.ConnectAsync()` 拉 HTTP 房间列表，**完全不启动 ZeroTier 节点、不加入自建控制器网络**。导致：
1. `RoomsViewModel.TryGetZeroTierIdentity` 拿不到 nodeId/virtualIp → 进房无法打 Tag。
2. 用户得手动切「自建控制器」模式连一次局域网，体验割裂且逻辑矛盾。

### 修复（客户端 kiriyamalauncher.Presentation/ViewModels/GameSessionViewModel.cs）
1. 抽出 `ConnectZeroTierAsync(bool allowOfficialFallback)` 私有方法，封装「启动节点 → 设 ConnectionMode → 绕 moon → 加入网络 → 报告虚拟 IP → 开自动注入/隧道」整套逻辑，返回 `bool`（transport ready）。
2. `ConnectToRelayServerAsync` 重构为两步：先 `ConnectZeroTierAsync(allowOfficialFallback: false)` 接入自建控制器网络（拿 nodeId+virtualIp），再 `Rooms.ConnectAsync()` 拉房间大厅。
3. `ConnectToVirtualNetworkAsync` 非 Relay 分支改为调用 `ConnectZeroTierAsync(allowOfficialFallback: true)`。
4. `ResolveNetworkId()` 增加 Relay 模式分支：Relay 与 SelfHostedController 一样返回 `SelfHostedNetworkId`（不再走官方网络回退）。
5. `DisconnectAsync` 的 Relay 分支：除了 `Rooms.Disconnect()` 清大厅，还做 ZeroTier 应用层断开（`DisconnectAsync(networkId)`，节点保持在线，libzt 无法真正退网）。
6. `RoomsViewModel` 两处「尚未接入 ZeroTier 网络」warning 文案改为提示「点击右上角连接到虚拟局域网」即可（不再引导用户切自建控制器模式）。

### 关键约定（勿再犯）
- **中继服务器模式（Relay）的底层网络就是自建控制器网络**：网络 ID 用 `SelfHostedNetworkId`，连接时同样要 `StartAsync` + `OrbitMoon` + `JoinNetworkAsync`，只是额外多一步 HTTP 房间大厅。二者共享同一套 ZeroTier 接入逻辑。
- 三种连接模式（Official / SelfHosted / Relay）中，SelfHosted 与 Relay 都绕 moon、都用 SelfHostedNetworkId；Official 用官方根 + ZeroTierNetworkId/默认网络。

### 关键约定 / 教训
- **`Ioc.Default` 没有 `GetServices<T>()`**（那是 `Microsoft.Extensions.DependencyInjection` 的 `ServiceProviderServiceExtensions` 扩展方法，作用在 `IServiceProvider` 上）。在 App.axaml.cs 能用是因为它有 `using Microsoft.Extensions.DependencyInjection;`，新文件用到 `Ioc.Default.GetServices<T>()` 必须同样加这个 using。
